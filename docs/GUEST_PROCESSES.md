# K3.2.3 — Cooperative RV32 kernel processes

RPKernel is a single-owner freestanding C process table bound to one shared RVFS. Two fixed slots contain isolated 4 MiB machine address spaces, CPU contexts and process-local descriptor tables. The process identifier is monotone within the kernel lifetime and is never reused on slot reclamation; exhaustion refuses new processes. No caller-provided process ID can allocate a slot. Spawn validates the ELF before publishing identity, checks capacity and standard-stream resources, then initializes the machine and descriptors. This is a trusted kernel API, not a guest process-creation syscall.

rp_tick(quantum) selects the next ready slot round-robin, executes at most the smaller of the quantum and remaining per-process instruction budget, and returns after the selected slice. A terminal result distinguishes exit, instruction trap, instruction-budget exhaustion and cancellation. Every terminal transition drops descriptor references; terminal metadata is retained until reap. rp_observe copies metadata without running the guest; rp_reap removes only terminal processes. Slots and RAM are reused, but logical identities are not. There is no preemption inside a syscall: a blocking device callback can block the entire scheduler. Callbacks must not reenter it. Effects already performed are not rolled back on trap or cancellation. No fork, execve, wait syscall, IPC, permissions or durable process migration yet.

The hosted native harness uses the real C scheduler and compiled descriptor ELF, not simulated tasks. Seven instruction quanta (1,3,7,15,31,63,127), fourteen completed guests with isolated RAM, descriptor-local state, shared structural file storage and exact persisted file values abcdE; both tasks advance in order. Tested invalid image admission, slot capacity, stale PID, premature reap, cancellation, one-instruction budget and an actual illegal-opcode trap. All open references released after terminal transitions. The prior descriptor and startup regressions and negative ELF checks passed locally, as did the structural file suite before the scheduler change. A combined invocation reached the environment timeout and negative ELF checks were rerun separately. No full fresh regression claim.

The independent boot image links the same scheduler and adds a pair command executing two copies of the compiled demo using bounded instruction slices. The QEMU test requires both outputs and successful reap. Boot image static validation passed: 50,812-byte file, BSS about 14 MiB including the original single-guest context, two process slots and fixed filesystem pool. QEMU unavailable locally and actual boot/serial pair execution unverified. The hosted normal ELF CLI still uses its single-process path; the scheduler is tested through a hosted C harness and linked into the boot monitor.

Virtual Layer opportunity: identity and scheduling are now distinct from machine realization. A later exact navigation backend may substitute a slice only if it preserves register, memory, logical instruction and effect semantics. Independent scheduling quanta already provide useful differential tests, but identical output for these noninterfering workloads is not a proof of arbitrary schedule independence.

Next: bounded pipes and explicit blocked/wakeup states, process lifecycle syscalls and a conventional pipeline, external executable admission from an archive, real libc and boot qualification.

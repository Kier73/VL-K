# K2.8 — Persistent fenced pure-process authority

Authority(path) stores admitted pure programs and replay-checked checkpoints in a local SQLite database. create establishes a logical process and epoch 1; head reads owner, epoch and checkpoint. transfer requires the exact current owner, epoch and coordinate, increments epoch and retains state. advance requires the same fence, a nonempty operation identity, and increasing exact u64 coordinates. It reconstructs and computes outside the write transaction, then rechecks the fence and complete starting row under BEGIN IMMEDIATE before atomically updating the checkpoint and inserting one durable publication. Identical retries under the same current ownership return the stored publication, not another advance; conflicting reuse or stale ownership is rejected. A different owner may read the historical publication list but may not replay a former epoch's advance through that method. SQLite INTEGER stores the bounded positive epoch; tick uses decimal strings inside canonical JSON to preserve u64.

The database is the single authority, not a replicated consensus protocol. Owner labels are trusted caller identities, not secrets or authentication credentials; direct database writers are trusted. Any actual remote service must derive the caller identity from authenticated local authorization. There is no automatic lease expiry or election on crash. Epoch changes require explicit trusted transfer. An external action is not exactly-once merely because a database publication is unique. Only pure state plus an internal publication are committed here; an external effect sink must implement its own durable idempotency/fencing, and arbitrary I/O cannot be safely replayed. Pure reconstruction reuses Session's admitted domain and dispatch limits.

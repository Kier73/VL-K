# K3.2.5 — Guest-directed computation

## Process transition boundary

A scheduled RV32 context enables a process-call event (rv_run returns 3 before retirement). Only the scheduler implements that event; the single-image hosted ELF runner retains its previous syscall subset. The process kernel supports getpid(172), pipe2(59, flags zero or O_CLOEXEC), fork-like clone(220, flags exactly SIGCHLD=17, null child stack and extra pointers), execve(221), and wait4(260, direct child PID or -1, options zero or WNOHANG, null rusage). All guest pointers are checked against guest page permissions before effects. Successful process syscalls retire once; a blocked wait retires only on resumption. No full Linux clone, signals, process groups, threads or ABI conformance.

Clone copies all 4 MiB of RAM and machine metadata, then returns zero at the next PC in the child, and its fresh PID in the parent. The child receives a separate instruction counter starting at zero and a limit equal to the parent's remaining budget after clone; this is per-child, not a conserved aggregate instruction budget. The parent retains its limit. The two fixed process slots support a root and one child, with terminal slots retained until reaped. Descriptor tables are copied but open descriptions are shared with reference increments, preserving offset and endpoint semantics. PID values are never reused (positive signed 32-bit range). The trusted scheduler owns process creation. Parent termination orphans its children to the trusted host, which must reap them. There is no init or automatic orphan reaper.

Exec names resolve only in an immutable caller-owned catalogue of at most four named images, not arbitrary host or guest paths. Registration binds trusted bytes and names for the lifetime of the kernel; actual ELF validation is performed at execution. Argument and environment vectors are copied from guest memory into bounded kernel scratch before staged loading (16 strings each, 255 bytes each). Failed admission leaves the prior machine and descriptors intact; successful replacement retains PID, parent, instruction accounting and non-CLOEXEC descriptors, and closes CLOEXEC references. No dynamic linker or full libc support. Wait selects only a direct child; invalid status pointers fail before reaping. WNOHANG returns zero without modifying status while the child is live. Blocking wait uses the same suspended continuation machinery as pipes and becomes runnable when a child terminates. Exit status is encoded as status<<8; trap and limit/cancel use coarse synthetic status values 4 and 9, not real POSIX signal delivery.

## Interactive guest shell

Build with make all dist/shell.rv32 dist/filter.rv32. Run:

    vlk session dist/shell.rv32 demo=dist/demo.rv32 filter=dist/filter.rv32

Commands: run NAME [ARG], send WORD | NAME [ARG], quit. Whitespace-delimited single words only; no general shell grammar, arbitrary multi-stage pipeline, job control, redirection, quoting or terminal line discipline. In send, the shell itself is the producer and its child is the consumer. The native session loads only explicitly supplied images, forwards standard streams and ticks the same C scheduler. It does not parse guest commands, fork host children or run host binaries. Session files are volatile; ordinary vlk elf volumes are unchanged. A blocked external stream callback can still block the entire kernel. Session refuses no-runnable/unreaped-child terminal cases. The freestanding monitor embeds the same compiled shell, demo and filter and provides a guest command; on return it cancels/reaps any remaining children and reports failure if needed.

## Evidence

Five actual compiled controller runs with quanta 1,7,127,1024,65536. Each creates a pipe, forks, validates failure preservation for missing and malformed exec and invalid pointers, executes a separately compiled worker, transfers 8192 bytes through a 4096-byte pipe, independently checks XOR output, validates environment and CLOEXEC behavior, waits for exit 23, checks private memory unchanged, rejects repeated wait, forks a second child, waits for exit 7 using -1 and reclaims all references. Ten child lifecycles, 40960 payload bytes, 15 blocked continuations and 15 wakeups; blocking wait observed at each quantum. Capacity and unsupported clone flags refused. Actual hosted guest shell ran demo, rejected missing, piped abc into filter Q yielding 032, and quit with status 0. Prior rvproc, rvpipe, descriptors, runtime, negative ELF, structural_files and fs suites passed through VL-K in split invocations; a combined invocation timed out before finishing structural_files, which passed separately. No fresh complete regression claim. Both native and freestanding build succeeded after replacing a compiler-generated memcpy dependency with explicit machine metadata copying; boot image 71532 bytes, no unresolved symbols. QEMU absent locally, independent boot and embedded guest shell not runtime-qualified. Standard Linux libc and third-party applications remain open.

## Virtual Layer opportunity

The parent now constructs a computational dependency through a conventional process interface. A child completion is an observation that makes a waiting continuation realizable; an exec is a changed implementation with preserved logical process identity. Future structural fork memory can use immutable/shared pages and copy-on-write to avoid the current full 4 MiB copy, provided private observations, writable aliases and syscall effects remain exact. This is a proposed optimization, not one used here.

Next: larger/dynamic process capacity, device readiness, guest filesystem executable namespace, standard libc and real upstream applications, actual boot and persistent block storage. Extend tests to arbitrary-length pipelines and process supervision with an independent executable corpus.

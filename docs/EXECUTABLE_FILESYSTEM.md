# K3.2.9 — Guest executable filesystem

Scheduled RV32 guests can install file bytes, change their mode with fchmod(52), and launch a filesystem ELF through execve(221). New regular files retain the historical default mode 0666 (openat creation-mode argument is still ignored); mode bits 0000..0777 are stored and statx reports them. The single-owner domain enforces owner read/write bits on new opens and owner execute bit on filesystem exec. Existing open descriptors retain access. Unsupported special mode bits are refused. No user/group identity, setuid, capabilities, directory traversal, general POSIX permission model or security sandbox is implied. fchmod is available in scheduled sessions, not the single-image ELF runner; existing V1/V2 data-only volumes restore files as 0666. Session files and modes are volatile, including the independent kernel until reboot.

The immutable host catalogue retains precedence for bare names, with filesystem fallback. Explicit ./NAME forces the flat guest namespace, bypassing catalogue precedence; names containing other slash components are rejected. No guest path maps to a host file. Files lacking owner execute permission or with any open writable description are refused (EACCES, ETXTBSY). A single-owner kernel copies the exact structural-file bytes into a bounded separate 256 KiB executable staging buffer. The established loader validates the ELF and startup vectors before replacing the process. A failed exec preserves its identity, memory observations and descriptors; successful exec preserves the logical PID and closes CLOEXEC descriptors. Executable staging remains a full byte snapshot, not zero-copy mapping. Filesystem execution remains RV32IM static ELF only.

The compiled shell now accepts install NAME SIZE followed immediately by exactly SIZE raw bytes (1..262144). It creates a new nonexecutable file exclusively, writes bytes through guest syscalls, then grants 0755 and closes it. A failed binary transfer attempts cleanup and exits the shell rather than interpreting unread payload as commands. A malformed size is rejected before reading payload. Install does not validate ELF itself; exec performs admission. Use run ./NAME ARG to launch. Example (POSIX host shell):

    make all dist/shell.rv32 dist/execfs.rv32
    (printf 'install newapp %s\n' "$(wc -c < dist/demo.rv32)"; cat dist/demo.rv32; printf 'run ./newapp kernel\nquit\n') | ./dist/vlk session dist/shell.rv32

The same compiled shell links into the freestanding image. Its guest command still uses the serial console; binary module transfer over an actual boot has not been tested.

## Local evidence

tests/execfs.py: six session cases per backend (12 total), both existing and pooled memory. A compiled controller installed the 8792-byte separately compiled demo without a catalogue, executed it twice, tested mode metadata, missing name, traversal rejection, execute permission, open writer, unsupported special bits, write denial, permission revocation, malformed-image failure preservation, unlink/recreate mode reset. With a filter registered under the same bare name, explicit ./ selected the file and bare name selected the catalogue. Compiled shell installed and launched the same image without catalogue, rejected truncated and duplicate transfers and oversized length. Earlier guest_control, descriptors, fs, structural_files, object_runtime and elf --negative suites passed locally. Combined fs/structural_files invocation exceeded timeout after fs passed; structural_files passed separately. No fresh full regression claim. Freestanding ELF 75956 bytes, no unresolved symbols, static Multiboot validation passed. QEMU absent locally; actual independent boot and standard libc remain open.

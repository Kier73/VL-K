# K3.2.7 — General page-object memory contract

A new freestanding-compatible C allocator (src/rvobjects.c) separates page content ownership from a process or address-space lifetime. This is a component qualification, not a replacement of the current RV32 runtime: rv32.c and rvproc.c are unchanged and still select the two-context COW implementation.

## Contract

One zero-initialized ROPool contains 512 possible dense payload slots (2 MiB fixed reserved backing) and 512 nonzero object records. Each zero-initialized ROSpace has 1024 virtual page coordinates (4 MiB logical address range), local mapped bits and pool-local handles. Handle zero means implicit zeros. A nonzero object describes a verified period of 1..16 bytes or a dense 4096-byte page. Sharing increments reference counts; no cross-process backing pointers exist. No independent global deduplication of equal objects is attempted. Refcount zero reclaims the object and any dense slot. Handles may be reused internally, never exported as durable identities.

Every mapped coordinate reserves capacity for one potential private dense object. With D dense objects, O live nonzero objects, R mapped-coordinate reservations, and C=512, maintain D <= O <= R <= C. A new map or fork checks the complete reservation and range before mutation. A shared object's split can use an existing reservation: if it has multiple references there must be at least one more reservation than live objects. Unique objects may reuse their slots. No late allocation failure due to insufficient backing under this invariant, even if all shared mappings diverge. This intentionally rejects overcommit rather than requiring an out-of-memory policy during instruction execution. The aggregate mapped-coordinate budget is only 2 MiB, not 4 MiB per address space simultaneously.

Reads reconstruct bytes from the selected object. Writes validate the complete range first and split only changed pages; each modified page is reclassified by exact full-page comparison. Unchanged writes preserve references. Unmapping drops the corresponding reference; remapping is zero-filled. Dropping an address space does not force survivor materialization. The single-owner API requires trusted zero-initialized structures, all spaces bound to the same pool, no external mutation of metadata, and caller-owned nonaliasing buffers. Permissions, ELF staging, process ownership, syscall scatter/gather and scheduling are separate unintegrated concerns. No persistent serialization, asynchronous access or thread-safety claim.

## Evidence

Native optimized and ASan/UBSan runs through VL-K passed: eight address spaces, 512 reservations, 64 periodic objects and zero dense pages immediately after fork; original owner dropped and recreated from a descendant without copying. 8,000 deterministic mixed operations against independent eager arrays, 512 full-page comparisons, and periodic refcount reconstruction. 448 shared-object splits and peak 511 dense slots during mixed workload; then forced all 512 mappings dense and verified capacity, invalid range refusal, zero remap and complete release. Separate overcommit rejection and periodic-to-zero reclamation. Freestanding i386 object compiled without undefined symbols (2769 bytes text). Existing compiled COW tests and guest control/shell tests rerun successfully; no full suite or QEMU claim.

Representation counts describe live logical content and occupied slots, not reclaimed host RAM; the pool backing is fixed. Writes currently scan/reclassify whole changed pages and are unsuitable as an unmeasured scalar-store fast path. Next: add fast unique-dense stores, explicit bounded reclassification, preserve full-range preflight, and integrate page-backed load/store plus bounded syscall buffers in the actual machine. Then expand scheduler process slots and compare compiled workloads to the existing flat backend, including maximum capacity, exec, mmap, faults, and process termination. Keep the current working backend until that qualification.

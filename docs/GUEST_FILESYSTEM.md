# K3.1 — Shared guest file namespace and hosted volume persistence

The hosted and freestanding RV32IM interpreters share src/rvfs.c. The flat namespace admits 8 regular files, each at most 256 KiB, 16 file descriptors (3..18) plus the three standard streams. Names contain 1..63 ASCII alphanumeric, underscore, hyphen or dot characters, except "." and ".."; slash, directories, symlinks and host path forwarding are absent. File contents are stored densely in fixed bounded arrays; seek holes are zeroed on subsequent write. Each open has its own offset, read/write mode and append behavior. File creation, exclusive creation, truncation, append, EOF, negative seek, close and unlink are supported. Open files cannot be unlinked (EBUSY); closed standard stream slots are not reused. Permissions are descriptor modes, not Unix uid/gid/mode authorization. Oversized writes fail rather than partially writing. O_LARGEFILE and O_CLOEXEC are accepted without extra semantics. Unsupported flags fail. This is a deliberately limited ABI, not full POSIX.

RV32 Linux-number syscalls added: openat(56, AT_FDCWD only), close(57), unlinkat(35, AT_FDCWD and flags zero), and RV32 llseek(62: fd, offset_high, offset_low, result pointer, whence), plus existing read/write extended to guest files. Guest pointers and permissions are checked before host or filesystem access; seek result is little-endian 64-bit. No stat family, directory enumeration, mmap, dup, general libc, dynamic linker or multi-process guest scheduling yet.

Hosted `vlk elf --volume FILE ELF [ARG...]` restores the volume or creates an empty one if absent. Without --volume, all files are volatile. A volume begins with 8-byte magic VLKFS1 followed by two NUL bytes, then repeated u8 name length, little-endian u32 data size, name bytes (no NUL), and file bytes. The parser rejects duplicate names, invalid names, excessive records/sizes and incomplete data. This is a bounded data format, not an authenticated or checksummed disk filesystem. Each cooperating process obtains a nonblocking flock on FILE.lock and keeps it through execution. The trusted host operator must consistently use the same path and keep the lock file; alias paths, noncooperating writers and hostile host-side links are outside the model. Guest filenames never become host paths. After successful guest exit 0, save writes a temporary sibling, flushes, fsyncs, and renames it over the volume. Nonzero exit or trap leaves the prior volume unchanged. No directory fsync or power-loss durability guarantee, and standard stream effects are not rolled back. Successful read-only runs also rewrite the volume. No arbitrary concurrent guest volume access or exactly-once external effect semantics claimed.

Freestanding kernel links the same filesystem and embeds the file utility alongside the existing demo. Its new serial monitor command 'file' runs the compiled utility to increment a file-backed counter. Guest registers, memory and descriptors reset between launches; the RAM filesystem survives until reboot. The QEMU acceptance test now requires two file invocations printing count 01 and count 02. No block device or persistent bare-metal volume implementation yet.

## Local evidence

Built hosted ELF runner and static i386 Multiboot image. Actual VL-K-supervised file workload, 16 native/guest command comparisons using the same C source (POSIX native wrappers and RISC-V syscall wrappers). 192 KiB input + 4 KiB append, XOR file transformation, full readback and tail, eight separate counter launches, unlink, seek gaps, independent open offsets, exclusive-create rejection, access-mode errors and 16-descriptor quota. Independent Python parser checked exact volume contents. Nonzero exit, oversized write, traversal name, busy lock and six malformed volumes refused with the prior file contents preserved. Tests/fs.py passed. Prior ELF regression: 40 native/guest argument comparisons passed via a separately run subprocess driver; 1 MiB byte filter checked against independent XOR and ABI assembly test passed separately; eight malformed ELF and four illegal-instruction/access traps passed through tests/elf.py --negative. The combined original suite hit the environment execution limit, so no uninterrupted full regression claim. Static boot validation passed, boot ELF 42016 bytes, embedded file utility 7548 bytes, no unresolved symbols. Runtime boot remains unverified: no QEMU or hardware virtualization locally, prior boot CI queued. E-CPU full checkout remains unavailable locally; no E-CPU change.

Next: standard libc startup/auxv, stat and mmap, larger memory, directory semantics, and an externally authored static application. On bare metal, actual boot validation followed by loading applications without rebuilding the kernel, interrupt/timer and storage drivers. Keep the same syscall and guest execution semantics between hosted and freestanding environments.

# K3.2 — ELF startup, anonymous memory and external Multiboot module

## Startup and staged validation

rv_load_env admits up to 64 arguments and 64 explicitly supplied environment strings, each shorter than 4096 bytes and collectively bounded by the 64 KiB stack. The stack is 16-byte aligned and contains argc, argv and null, envp and null, then auxiliary key/value pairs ending in AT_NULL. AT_PAGESZ, AT_BASE=0, AT_ENTRY and (if argc>0) AT_EXECFN are supplied. AT_PHDR, AT_PHENT, AT_PHNUM are supplied only when the actual complete ELF program header table is contained within a readable PT_LOAD file range. No fabricated AT_RANDOM or claim of a complete libc startup ABI. Hosted CLI accepts [--volume FILE] then repeated --env KEY=VALUE before the executable; it does not inherit the host environment.

The loader first runs the same validation against a temporary machine metadata record without writing destination memory. Only an admitted image enters the materializing pass. Source image and host argument strings must remain immutable and disjoint from destination memory during the call. The checked failure guarantee covers invalid image and argument layout, not host pointer faults, concurrent source mutation or atomic publication of external effects. A native test compared the entire existing machine and all 4 MiB RAM after two late validation failures: unmapped entry and oversized environment string.

## Anonymous memory

RV32 Linux mmap2(222) accepts positive bounded size, MAP_PRIVATE|MAP_ANONYMOUS, fd=-1, page offset zero, non-fixed advisory hint and read/write/execute protection bits excluding W+X. It searches downward from the reserved stack, above the current brk, and zeroes allocated pages. A distinct allocation bit keeps PROT_NONE reserved. mprotect(226) and munmap(215) operate only on wholly allocated anonymous-map ranges, aligned start and page-rounded size. Full-range checks precede mutation. brk growth refuses collisions with mapped pages. No file-backed mmap, MAP_FIXED, hole-tolerant Linux munmap, protection changes on ELF/heap/stack pages, configurable RAM or full Linux semantics. No change to RV32IM ISA coverage, file metadata, TLS, signals or threads.

## Independent boot module

Multiboot v1 header requests basic memory information; entry passes both boot magic and information pointer. The kernel accepts exactly one optional module, with bounded descriptor range and nonempty image size <=4 MiB, above the linked kernel end and within the reported upper-memory extent. Boot information is trusted from the bootloader; this is not a full physical memory-map parser or validation of hostile firmware. The serial command external loads the supplied bytes into the same interpreter and runs with argv external/kernel and MODE=vlk. This replaces no embedded fixture; the demo and file commands still exist. The module is not copied into the kernel executable. No block storage, external-module disk filesystem, dynamic module insertion or kernel persistence across reboot.

make boot dist/runtime.rv32 builds both artifacts; qemu-system-i386 -m 32M -display none -monitor none -serial stdio -kernel dist/vlk-boot.elf -initrd dist/runtime.rv32 should load the module. make boot-test checks actual QEMU boot, existing demo/file commands, external module admission, compiled runtime output and halt. QEMU unavailable locally, no successful independent boot or module execution claimed.

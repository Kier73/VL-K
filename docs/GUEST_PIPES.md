# K3.2.4 — Communication dependencies and suspended guest continuations

The RVFS object table now admits two bounded 4096-byte FIFO pipes with read/write open descriptions. A descriptor duplicate shares its open description; closing the final reference closes the corresponding endpoint. A nonempty read consumes bytes in order. Empty reads suspend while a writer exists, or return EOF when none exists. Writes up to the capacity are all-or-block, larger writes can return a partial count, and no-reader writes return -EPIPE (no SIGPIPE signal delivery yet). Zero-length operations return zero. Pipes are volatile kernel objects, not persistent volume files. Seek is refused. statx identifies a FIFO, but metadata and flags remain a limited ABI.

Trusted rp_connect links stdout of one fresh ready process to stdin of another, before either executes. Endpoint allocation precedes replacement of the original descriptors. The existing guest read/write syscalls need no application changes. This is not yet guest pipe2/fork/exec, a general shell pipeline interface, multiwriter POSIX conformance, or a nonblocking host-device API.

When the pipe cannot realize a read/write, it returns an internal sentinel before mutating bytes or registers. rv_run returns 2 before the ecall advances PC or increments retired instructions. The scheduler retains the machine and marks the process BLOCKED. On the next scheduling call it evaluates readiness of each blocked pipe operation from its preserved argument registers. A ready, EOF or broken-pipe transition becomes runnable; the original instruction is retried. Blocked guests do not consume instruction quanta. A scheduler return 0 means no runnable process, not necessarily that every process exited. Cancellation can retire a blocked process and drop endpoint references. There is no preemption of an external blocking I/O callback, arbitrary deadlock recovery, or asynchronous event loop. The finite two-slot readiness scan is a kernel operation, not guest busy-waiting.

The tested computational relation is a dependency-driven continuation: at a blocked ecall the process state remains at the same instruction coordinate; channel state determines whether its next transition is currently realizable. EOF and error are also sufficient observations. The kernel's scheduler scans a bounded table rather than navigating a general dependency graph. No claim that passive communication performs arbitrary computation.

## Evidence

Actual hosted C scheduler through VL-K, two compiled copies of the existing RV32 filter using ordinary read/write/exit: five pipelines, 64 KiB pseudorandom input each, double XOR roundtrip exact; total 320 KiB transferred through 4 KiB buffers. Quanta 1,7,127,1024,65536 yielded blocked/wake counts 1,2,2,2,31 respectively (38 total, excluding cancellation test). Native endpoint checks verify empty blocking, atomic small writes, wraparound, duplicate writer lifetime, EOF and EPIPE. Cancellation of a writer while reader blocked preserved reader PC/registers/retired instruction count before the subsequent EOF continuation; both processes reaped, all pipe and open references released. Prior process, descriptor, structural-file, runtime and negative ELF suites passed locally. Freestanding image linked and static validation passed (54,984 bytes); actual QEMU boot not executed. No full regression pass or real libc compatibility claim.

Next: expose guest pipe2, process creation/wait, external executable launch and a conventional pipeline shell; distinguish no-runnable from completion and provide event-driven device wakeups. Preserve exact syscall/effect boundary when investigating Ground-based execution slices.

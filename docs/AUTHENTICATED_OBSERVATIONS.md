# C0.6 — Authenticated historical observations

ObserverHost admits a single exact retained receipt and a finite receiver-owned coordinate set. It realizes an admitted page through the existing GroundHistory and unchanged E-CPU PageGroundBacking. It does not offer remote write, branch, flush or arbitrary execution authority. Store opening may perform the existing identity-schema check/migration; this is a read-only network operation policy, not a filesystem read-only mount.

The request binds protocol version, observe operation, caller nonce, pinned receipt and coordinate. The response echoes the nonce and carries the portable coordinate witness. The independent coordinate-witness.mjs verifier checks the page against the caller's retained root and coordinate. Neither peer TLS identity nor a response nonce authenticates the underlying Ground root: root admission is external. Repeating the read-only intention after host loss is permitted; the nonce binds the response, not an exactly-once or replay-protection protocol. A sibling digest may disclose information about other coordinates; no privacy-preserving proof claim.

Local pathway reuses VL-K python/effect_transport.py bounded framing (send/receive) and prior observation test certificate fixture; TLS requires CA verification, TLS 1.2+ and the expected observer DNS SAN, while the caller checks server hostname. One request per connection, finite socket timeouts; local operator owns certificates, policy and listener. Test server catches refusals and closes connection. Not a production service, no concurrent accept policy, distributed write fencing, revocation or online discovery.

Native adapter directly calls E-CPU mailcpu.mtls_transport.accept_mutual_tls/connect_mutual_tls and mailcpu.model.Message with the existing framed SocketTransport from pinned revision 09a9058a43c139c476609954636e17e7fadcfd37. The same request admission and detached verification apply, and the native message frame limit is 16 KiB. A separate CI job checks out that revision and runs the same suite with VLK_NATIVE_ECPU=1. Native transport execution remains unqualified locally: GitHub DNS resolution fails and the native checkout is not present. Local qualified transport is the existing VL-K TLS framing, not native E-CPU transport. E-CPU PageGroundBacking is actually used in both configurations.

# K3.2.6 — Structural fork memory

The two-slot cooperative RV32 process kernel now shares mapped pages at fork. The underlying preallocated 4 MiB RAM per slot is unchanged; this reduces payload copying rather than reserved RAM. A borrowed-page bit projects a logical page to its peer's backing. Source and peer are distinct trusted kernel contexts, and at most one borrows any given page. Fork copies machine metadata and marks every allocated page, including inaccessible anonymous mappings, as borrowed by the child. No payload bytes are copied. The implementation remains single-owner with two slots, no arbitrary alias graph, no host-thread concurrency or guest shared-memory mappings.

Scalar instruction fetch, load, and guest string/argument reads resolve the appropriate backing; an aligned scalar access stays within a page, while unaligned syscall word reads handle page boundaries. Before a store or destination-buffer write, materialize a borrowed local page or preserve the peer's borrowed page, then mutate local bytes. Bulk syscall buffers must be contiguous; input to a kernel operation can materialize borrowed pages even if the guest itself does not write. All callers validate ranges and access permissions first. The syscall buffer is borrowed only synchronously; callback code must not retain it, reenter or modify a write-to-device source buffer. Pipe readiness is checked before buffer materialization. Mapping and heap growth preserve any peer observation before zeroing; unmapping drops the local borrowed bit. Protection changes remain per-context. The helpers are trusted internal operations, not independently hardened user APIs.

When a peer retires, the survivor's borrowed pages are materialized before releasing the relation, while the retiring context's borrowed pages need not be retained. Terminated machine payload is not a supported observation. Exec validates the new image and all startup data before releasing the relation and replacing the old memory; malformed exec leaves the live representation unchanged. These invariants avoid dangling references to reused slots. Counters measure actual copied payload pages and shared mapped pages at fork; they exclude initial loads, zero fills, metadata, reserved backing capacity and runtime overhead.

## Local validation

Five thousand deterministic mixed reads and writes against two independent eager byte arrays; explicit owner and borrower release, read without copy and zero-payload fork checks. Four compiled guest fork workloads using quanta 1,31,1024,65536: 1 MiB anonymous mapping populated, inaccessible page preserved across fork, parent writes before child reads, cross-page pipe destination, independent child writes, mprotect, unmap/remap and zero-fill verified, child status and parent's original data verified. All four shared 273 pages at fork and copied five payload pages through termination (20 KiB versus prior unconditional 4 MiB fork copy, 204.8x fewer bytes for this workload). This is not a timing benchmark. All four completed and released peer relations and open descriptions. The native eager oracle and compiled guest are separate tests.

Existing guest_control, rvproc, rvpipe, descriptors, runtime, elf --negative, structural_files and fs passed locally through VL-K. A combined invocation timed out before negative ELF completion; the negative cases passed separately. No fresh full regression claim. Hosted and freestanding builds succeeded; static boot ELF 71724 bytes, no unresolved symbols; QEMU unavailable, actual independent boot unverified. No real Linux libc qualification or third-party application claim.

Next: replace pairwise borrowing with a bounded physical page-object pool and reference ownership to support more than two processes and reclaim reserved memory. Expand executable namespace and ordinary shell pipelines, standard libc, external storage and actual boot qualification. Measure actual execution costs before making the structural optimization universal.

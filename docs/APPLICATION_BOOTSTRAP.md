# K2.9 — Applications, effect publication, and Ground discovery

## Guest applications and output boundary

vlk app PROGRAM INPUT AUTHORITY SINK JOB executes a validated guest program with a pinned input file (up to 64 KiB), a fresh 64 KiB zero-filled address space, and bounded output (64 KiB). Guest readfd d,f reads a byte from the read capability in register f (0xffffffff at EOF); writefd f,s writes the low byte of s to a writable descriptor. fd0 and fd3 alias the same read-only source, fd1 is write-only output; other descriptors are denied. The ordinary read/write instructions alias the same streams. No guest path lookup or unrestricted syscall. The debugger remains pure: application validation is opt-in. Up to 4096 instructions in the program, two million logical instructions and ordinary dispatches, existing path work bound. Failed or nonzero-exit applications publish nothing. This is a hosted guest application, not Linux ELF or POSIX syscall compatibility, nor a general sandbox.

Applications reuses the local SQLite transaction/fence contract. Register pins code and input; identical submission at epoch 1 is retryable. Transfer is explicit and changes the owner/epoch; the CLI uses local owner at epoch 1. run_job computes outside the lock and atomically admits one immutable outbox payload under a rechecked fence. Existing matching output can be retrieved by the current owner without execution. The outbox is a committed logical effect, not a general process snapshot; delivery may continue after owner transfer. Sink is a separate trusted SQLite consumer with job-key uniqueness, receipt/payload comparison and transactional insert. Deliver retries the committed immutable payload, then acknowledges in the authority database. Crash after sink commit but before acknowledgment is recoverable; duplicate deliveries do not insert a second record in that sink. Caller must keep job IDs unique per sink and use the same trusted sink for retries: acknowledgment is not per-sink identity, direct database writers and sink selection are trusted, no external filesystem or network action is claimed exactly-once. No distributed consensus or full effect-aware guest checkpoints.

Local test executed 16,384 input bytes, 114,697 guest instructions, exact XOR output against native Python. Actual child killed after sink commit before ack; eight concurrent delivery retries and four more retries, one sink record for job; transfer between epochs; stale owner, uncommitted delivery, incorrect descriptor rights, output limit, conflicting submission and sink receipt rejected. CLI executed twice with same job; second invocation returned prior output; two jobs total in sink. SQLite integrity_check passed.

## Discovery and admission of a smaller selector Ground

For x in Z/(2^32), an original case table of power-of-two size m selects T_p(x)=a_p*x+b_p, p=x mod m. A candidate quotient of size d dividing m selects representative T_(p mod d). The maps need not have identical coefficients: on the entire original residue class x=p+m*k they agree iff both (a_p-A)*m and (a_p-A)*p+(b_p-B) vanish modulo 2^32. This follows by substituting x and checking constant and slope; the necessity of the slope condition is immediate for m<2^32. All admitted m are <=4096. Since d divides 2^32, the reduced selector is closed. Induction proves trajectory equality and the original selector can be reconstructed from the realized x. discover searches increasing powers of two using existing first-d row representatives. It proves the smallest such candidate, not the smallest possible synthesized law among all representations. Construction worst-case O(m log m) comparisons; observation uses existing path navigator over d cases. No trace or effect equivalence beyond final state and original residue. This service is opt-in; it does not yet replace arbitrary guest loop lifting.

vlk ground TABLE takes a JSON array of [a,b] pairs, reports admission, then accepts newline JSON {"x":u32,"count":"u64 decimal"} and returns x, original phase, charged path work and method. Table bounded by existing file loader and discovery validation; input lines are not independently size-capped. It is a local trusted research CLI.

Local actual research: 100 constructed randomized tables and 2000 direct iterative queries; a constructed 4096-row table whose coefficients vary by residue reduced to 2 cases after 4098 checks. A one-row b+1 mutation forced retention of all 4096 cases. 64 random u64 observations matched full-table navigator, an independent modular formula, and unchanged E-CPU RRNS affine orbit utility (verified blob cb1d4ba145c584c437bf38f17f2899d50f83728c at commit 09a9058a43c139c476609954636e17e7fadcfd37). Charged path work 643089 -> 6242 (separate 4098 construction comparisons, excludes table validation and Python overhead). One local measurement full 0.297650 s, reduced 0.001887 s, construction 0.002464 s; not a repeated benchmark or general speed guarantee. Actual vlk ground process served all 64 queries via supervisor pipes. The table was constructed to have a hidden quotient; no claim of naturally occurring arbitrary workloads or universal reduction.

# K2.6 — Pure guest inspection and continuation

Run make all; export PATH="$PWD/dist:$PATH"; vlk debug examples/guest-debug.json. Commands: status; observe T (absolute coordinate, no mutation); step N (advance N logical instructions); save PATH; quit. Resume using vlk debug PROGRAM --restore PATH. Responses are one JSON line each. Tick is a decimal string to preserve exact u64 coordinates in JSON consumers. API Session.observe(t), advance(expected,target), status(), checkpoint(), restore(program,envelope). Advance reconstructs on a detached candidate, rejects stale/retrograde coordinates and commits only when the exact requested coordinate is reached. Halted sessions cannot advance past termination. All registers and PC, halt and exit status are represented.

The admitted domain is a bounded immutable pure register/control-flow program, all-zero genesis, with no I/O, memory, repeat instructions or external effects. Strict whole-program validation permits set, mov, add, mul, xor, and, jmp, jnz, halt. Up to 4096 instructions; CLI files capped at 1 MiB; each realization allows 100000 ordinary dispatches and existing path-work budget. Exact large jumps can occur within those limits; nonnavigable requests may refuse. Failed advances leave state unchanged. Checkpoint/observation reconstruct from genesis; a session advanced through many small steps may be unable to reconstruct its coordinate within the dispatch limit. These limits do not meter failed recognition attempts or wall time. This is not a security sandbox, process migration authority, or general VM snapshot.

Version-1 envelope includes program digest and complete observed pure state, bound by SHA-256 canonical JSON. Receiver requires exact original program, reconstructs from genesis with the same guest/navigator and checks canonical envelope equality; this is replay verification, not a separate proof implementation or signature. Save fsyncs a temporary file and atomically replaces the target in the same directory; no directory fsync or power-loss durability claim. A valid checkpoint may be restored multiple times; no exclusive ownership, generation fencing or external-effect replay ledger. Only trusted callers should grant continuation authority.

# K2.7 — Receiver-owned pure guest observations

The request schema is version 1, program_sha256 (canonical validated guest program), tick (canonical unsigned decimal u64 string). A receiver owns a finite catalogue of pure programs and a maximum logical coordinate. It does not accept program text, guest I/O, filesystem paths or caller-supplied execution authority in the observation payload. The existing Session limits apply. The result binds the request digest to a replay-checked checkpoint; the requester verifies by reconstruction against its own pinned program. SHA-256 identifies content, not signatures or ownership. Independent modular arithmetic checks supplement same-implementation replay.

The test fixture tests/observation.py uses bounded length-prefixed JSON over a real loopback TCP connection, mutual TLS and an explicit client DNS SAN allowlist. It is not a production listener. Ephemeral OpenSSL test certificates are generated in temporary storage. The first test run failed under strict CA key usage checking; adding explicit critical CA basic constraints and key usage fixed it without weakening TLS validation. No secrets are committed.

Local make all, observation and debugger suites passed. Separate receiver process admitted a 118-byte canonical request for tick 32212254723 and returned a 494-byte canonical result (application payload only, excluding original installed program, transport and TLS). Two unauthorized peers (missing client cert and CA-trusted wrong DNS SAN), four malformed/out-of-bounds requests and a forged response with recomputed digests were rejected. After the receiver exited, a fresh native-launcher debugger resumed from the transported checkpoint for five instructions and halted at tick 32212254728, state independently checked by modular closed form. Same machine, separate processes. No full regression rerun in this pass.

E-CPU adapter: ObservationHost.handle accepts a typed HypervisorArbitrationEvent for operation "observe VL-K pure guest coordinate", resource "/cpu/vlk/observe", exact required and granted rights {"execute"}, non-destructive. The receiver must run its capability gate before calling this method; it cannot derive authority from an untrusted event. The E-CPU contract was examined at commit 09a9058a43c139c476609954636e17e7fadcfd37, mailcpu/transit_compute.py, classifier.py and tests/test_transit_compute.py. The E-CPU runtime is not installed locally and GitHub checkout failed due to DNS. The actual E-CPU adapter has not been executed in this pass; the TLS test fixture is independent, not E-CPU transport. No E-CPU repository changes. This is observation, not exclusive process migration. Pure results can be reconstructed by multiple observers; no live memory, device, stream or effect state is transferred. Network authentication does not itself grant execution authority.

# PAC-001 — Procedural application continuity

A real JSON-lines terminal process provides an explicit application-state adapter. It is not an arbitrary application or OS process checkpoint implementation. The rover state is four modular u32 registers, terrain seed, opaque note bytes and logical u64 tick. The driver evolves as x'=2*x*x+3, force c'=x'*z, position y'=y+c', velocity z'=z+3 modulo 2^32. Terrain tiles are generated from seed and coordinate by SHA256; frame is a pure observation. External impulses alter velocity and optional binary note replacements are stored exactly in an ordered input journal. Inputs at tick t are applied before the observation at t (same-tick events retain their original order). Logical tick is not host wall time.

The application executes ordinary per-tick arithmetic during tick commands. Reconstruction and forward navigate split the timeline at external inputs and use the actual C0.14 driven binding and C0.8 dispatcher, with an independently BigInt-checked bounded eager reference binding for short segments. Long intervals use phase-stable driver specialization and affine powers, not event-free iteration. All journal events up to the requested coordinate must still be processed. This is explicit source-law integration, not automatic inference of arbitrary application's motion. The source identifier binds the declared law/version and observation/event conventions, not a cryptographic hash of all executable dependencies.

## Publication and continuation

The JSON manifest holds the version, law identity, initial seed, ordered events, head coordinate and head state SHA256; no full state sequence or even a head register dump. The trusted caller retains a separate manifest digest. Restore validates the receipt, bounded geometry and event order, reconstructs and checks the head, then reconstructs the selected historical coordinate, keeping only its event prefix. This creates a separate logical continuation if saved to a different path. A valid manifest digest is a commitment, not authenticity or authorization. A recomputed manifest digest with a false head commitment is rejected. Historical observations rely on the qualified source law and admitted event record, rather than individual stored commitments.

Save writes a new private temp file, fsyncs it, renames it and fsyncs the parent directory. It is a local single-writer POSIX publication pattern; no multiwriter CAS, tested power-loss semantics, remote authority, rollback protection or whole-machine checkpoint. Errors after rename can leave publication ambiguous. Autosave is optional via VLK_AUTOSAVE, after tick/input/navigate commands; failures are reported but do not roll back live application state. No continuous asynchronous capture between commands. Caller must retain the returned digest and preserve separate paths for alternate continuations. Max 512 inputs, 4096 opaque bytes per note, 3 MiB manifest, 100000 ticks per live command; local CLI trusted. No concurrent calls into a Rover session are supported.

## Use

Run node js/rover-session.mjs; send JSON-line commands, e.g. {"op":"tick","count":120}, {"op":"input","impulse":-9,"bytes":"AP8BAg=="}, {"op":"observe"}, {"op":"save","path":"rover.json"}. Set VLK_AUTOSAVE=rover.json to publish after each mutating command. Run node js/rover-session.mjs rover.json DIGEST [TICK] to continue in a new process. Supply the digest from the saved receipt and omit TICK for the latest head. Commands return the exact state, procedural frame and save receipt if applicable. Navigate accepts an exact decimal string tick at or beyond the current coordinate.

# C0.1 — adopt the full conventional source and release boundary

The source submodule vendor/unkernel pins fd204d3130309c45ce51795c753c3b8ec1eaddfd. Initialize it using git submodule update --init vendor/unkernel. This retains upstream history and licensing, without mixing its GPL-covered code into the original VL-K core. Source changes can subsequently be developed in an upstream-derived fork with appropriate notices, corresponding source and build instructions. No VL-K licensing choice is implied.

Run bash compat/unkernel/prepare.sh to acquire the pinned package and both distro images. Package and images are SHA-256 verified before extraction; the embedded kernel is verified against the standalone release digest. The 5,756,787-byte package already contains the 11,318,520-byte uncompressed kernel; no duplicate download needed. Alpine is 4,046,848 bytes and Debian 77,819,904 bytes. Binary artifacts live in ignored dist/unkernel-compat, not Git. Trusted local extracted files are used after preparation.

With Node >=24 and JSPI, bash compat/unkernel/run.sh alpine (or debian) starts the upstream interactive CLI with a 512 MiB memory budget, networking disabled by default and no implicit host mount. Explicit operator CLI options are forwarded, e.g. --data /absolute/path/experiment.img for upstream persistent ext4 storage. This is upstream execution, not a new original VL-K kernel boot. The wrapper is not a security sandbox, and forwarded flags can change the policy. Actual interactive boot and persistent volume reopen remain acceptance gates.

## First bottom-up substitution

StructuralDisk implements the inline upstream BlockDevice read/write scatter/gather contract with 512-byte aligned requests and 4 KiB independently represented pages. Absent pages are zero, exact periods up to 16 bytes retain patterns, otherwise a dense page is stored. Requests validate total range and all view types before mutation; writes own copies, reads reconstruct exact bytes, classification occurs once per touched page. Single-owner synchronous memory-only API, at most 64 MiB logical size. No durability, snapshot, overcommit, resource isolation or crash-atomicity guarantee. No automatic flush/discard capability advertised. Logical payload counts exclude map/array metadata and JS engine overhead. This is a new VL-K implementation, not copied upstream code.

Local Node 22.16.0 results: 2 MiB periodic disk represented by 3584 pattern payload bytes; 3000 mixed aligned read/write operations with varying scatter/gather splits against independent dense bytes; complete byte comparison, invalid range rejection without changes, write-input ownership, zero reclaim. Shell/JS syntax and missing-JSPI refusal passed. DNS blocked acquisition; upstream guest tests not executed locally. CI checks source pin, obtains artifacts, runs the independent disk oracle, then boots Alpine and Debian and tests ordinary guest process/filesystem behavior plus raw /dev/wdb writes and reads against the structural host device. This is a proposed Linux integration acceptance, not a passed Linux test. The temporary structural disk is separate from the upstream read-only distro and does not replace persistent ext4 yet.

Next: after C0 CI, qualify persistent disks and ordinary packages (Python, SQLite, compiler), then run Linux ext4 over a durable structural disk with independent recovery and flush semantics. Retain the upstream reference backend. No change to original RV32 research kernel.

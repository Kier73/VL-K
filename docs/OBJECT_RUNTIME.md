# K3.2.8 — Selectable page-object execution

Build make all dist/shell.rv32 dist/filter.rv32 and run dist/vlk-session-objects dist/shell.rv32 demo=dist/demo.rv32 filter=dist/filter.rv32. This is the original RV32 interpreter and scheduler compiled with RV_OBJECT_BACKEND, RO_OBJECTS=1024 and RP_SLOTS=4. The default hosted and bare-metal builds continue selecting the established flat/pairwise COW backend. No ISA or guest syscall-number change.

The pooled scheduler reserves 1024 potential dense pages (4 MiB aggregate) across four 4 MiB logical address spaces and shares a separate 4 MiB scratch region for ELF staging and synchronous contiguous syscall I/O. It has no private flat RAM array per process. Fixed pool and scratch are still reserved; live dense occupancy is not physical RAM usage. Loader validates candidate layout and reservation capacity before releasing old objects, then imports admitted pages; all-zero and short-period pages retain exact representations. Maps and heap growth reserve capacity, unmap and termination release references; fork admits the full worst-case reservation and shares object IDs. Admission can fail earlier than flat mode due to different capacity. Scalar accesses resolve page objects. ro_store validates full range and directly updates unique dense pages; changed zero/periodic/shared pages materialize once instead of scanning every write. Exact classification via ro_write remains available for explicit construction, not automatic recurring scalar compaction. Shared-object split counter is not a count of all page copies.

The loader and synchronous I/O use the shared scratch exclusively; trusted callbacks must not retain buffers or reenter the scheduler. Reads copy back only the returned positive byte count, after validating the complete requested range; writes gather the requested bytes before the operation. Pipe readiness is checked before gathering. Metadata and process syscall writes use small validated local buffers. The reservation invariant remains D <= O <= R <= C. Trusted internal helper calls require validated ranges and a zero-initialized, single-owner kernel. No page-pool persistence, overcommit, asynchronous callbacks, security sandbox guarantee, general Linux conformance or boot-runtime qualification.

## Evidence

Actual compiled fork workload on flat and pooled variants across four quanta: identical parent 3481 retired instructions, 273 shared mapped pages, memory/pipe/protection/unmap assertions and exit. Four concurrently scheduled compiled demos each retired 38177 instructions with identical expected output. Pooled peak 264 occupied dense pages, 20 shared-object splits across the campaign; zero live objects, reservations and descriptor references after cleanup. Capacity refusal before publication and pooled compiled startup/auxv/mmap/mprotect/brk probe passed. Five guest-created pipelines, ten child lifecycles, 40 KiB transferred and 15 blocks/wakes passed on the two-slot pooled qualification configuration. Four-slot pooled guest shell matched original transcript. The independent 8000-operation page oracle now mixes exact classification with the new fast store path, then fills all 512 slots and reclaims them. Existing COW, process, pipe, descriptor, runtime, malformed ELF, filesystem and structural-file suites passed through VL-K across split calls. Default freestanding image links (71784 bytes); actual boot remains unverified and QEMU unavailable. Combined test invocations reached timeouts; no fresh full-suite claim. No standard Linux libc or upstream application claim. No wall-clock speedup claim.

# C0.3 — Historical coordinate Grounds using actual E-CPU code

The storage substrate now has a persistent historical coordinate index with an unchanged E-CPU page backing. This is an independently qualified Python component, not yet selected by the JavaScript BlockDevice or actual Linux guest. Existing GroundDisk and original kernel remain available.

## Direct reuse

compat/unkernel/reused/page_ground.py is byte-for-byte mailcpu/page_ground.py from E-CPU revision 09a9058a43c139c476609954636e17e7fadcfd37, Git blob 2697208d5549cc90fb914824728590d3fa011dc6. The upstream MIT license accompanies it. GroundHistory actually instantiates PageGroundBacking and calls put_page/get_page/counts/close; no replacement codec. Raw, compressed and one-hop XOR representations share native SHA-256 page identities. Candidate basis index bounded by upstream contract. This imports a small self-contained mechanism rather than all of E-CPU. Other repositories were surveyed for observation, revision, authority and memory modules; they are not runtime dependencies of this pass.

## Coordinate law

Fixed power-of-two 4 KiB page geometry 2..16384 pages (64 MiB maximum logical). Empty subtrees are represented by a sentinel; leaves are native page digests, internal nodes hash domain, level and ordered child digests. Receipt root is a Merkle coordinate commitment, not the full logical byte SHA256 of GroundDisk v1. Geometry and Ground version are needed with root; revision numbers are database-local, not globally unique. Same contents in the same geometry yield the same root regardless of update order, subject to hash assumptions. A requested coordinate follows at most log2(pages) internal nodes; each visited node is rehashed, nonzero leaf reconstructed and checked by E-CPU backing. No history replay or full disk scan. A write to k distinct pages constructs at most k*depth new node rows; intermediate nodes may be retained. Read_range and aligned write_range use exact page observations; write_range merges partial pages and publishes the whole batch against the expected branch revision. Range requests can span full disk; memory/time depend on length. No whole-disk constant-time claim.

SQLite single database stores immutable pages, nodes, revisions and branch heads. Pages are retained by upstream independent commits first, then BEGIN IMMEDIATE checks branch revision and publishes path nodes and new revision/head atomically. Competing writers can retain unreachable staged pages, but cannot publish two different successors to the same branch head. A fork creates another branch pointing at an existing revision; no page copying or replay. No-op root keeps prior revision; zero write collapses empty subtrees. All history is retained; no GC, quota policy, authenticated or distributed authority, external effect fencing, signed receipts, replication, full snapshot, or crash injection mid-publication. Local trusted DB metadata supplies roots and authority; hashes alone do not authenticate them. Initialization assumes trusted exclusive setup; existing database creation may admit bases before a geometry mismatch. No adversarial DB/path guarantees. Page identity collisions and the all-zero digest sentinel are treated as cryptographically negligible.

## Local evidence

64 one-page revisions over 64 MiB logical space; seeded incompressible immutable basis and sparse mutations selected actual E-CPU XOR codec 64 times with one raw basis. At most 14 new node rows per single-page update. 1,000 historical coordinate observations against independent eager sparse-state maps; fork from initial revision, independent branch, no-op, cross-page sector write and byte-range read, equivalent roots, zero reclamation, invalid range and stale revision refusal. Two fresh processes compete at one revision: one succeeds, one returns conflict; fresh reopen preserves old and new observations. Modified coordinate node rejected while independent branch remains readable. Python 3.13 local test and py_compile passed. No timing or SQLite physical-size reduction claim. Added to conventional CI; no local Linux guest, JSPI, or ext4 qualification. No original-kernel regression in this pass.

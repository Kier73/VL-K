# C0.4 — Historical Ground block pathway

HistoryDevice implements the asynchronous upstream BlockDevice interface via a persistent Python interpreter over local child stdin/stdout. It invokes the existing GroundHistory and unchanged E-CPU PageGroundBacking, not a second codec. Node owns request ordering and copied write inputs; Python owns staged pages, native admission and durable CAS publication. This is a trusted local process pathway, not an authenticated E-CPU transport or distributed authority.

Geometry is fixed by the database (2..16384 power-of-two pages). Requests are sector-aligned, up to 1 MiB, with arbitrary scatter/gather splits; the worker limits input frames to 2 MiB and uses base64 inside JSON. Adapter permits at most 32 outstanding operations; one in flight, FIFO; overflow rejects. Per-response timeout 30 seconds. No general untrusted-protocol hardening; worker stdout is trusted and readline is not a bounded parser for adversarial output. Pending flush waiters are caller-lifetime dependent. The bounds are initial policy, not yet qualified against Linux workload request sizes.

A worker pins its branch head at open. Reads see staged updates then the pinned revision; a write stages all touched pages before acknowledgement. Flush commits the batch via GroundHistory CAS and clears staging; no-op root preserves revision. Flush sequence and whenFlushed implement upstream completion tracking; failure terminates the pathway, rejects pending work/waiters, and requires reopen. A queue-full refusal does not poison the pathway. No automatic retry of possibly committed effects after lost acknowledgement. Reopening resolves the durable branch head; staged data lost on worker termination is deliberately not durable. close drains queued calls, closes stdin and waits for process close; it does not implicitly flush. abort terminates the worker. No crash injection during SQLite publication, host power loss, or exact-once remote effects claim.

fork creates a branch from the currently pinned, clean revision; subsequent worker sessions can open either branch. A receipt binds Ground version, geometry, branch, revision, Merkle coordinate root and dirty bit. Root identifies the committed state; dirty observations may differ. No snapshotState or snapshotSeal capability is advertised because database-global identity and external device-generation validation are not yet established.

## Evidence

Node 22/Python 3.13 local tests: 250 paired queued writes/reads, 12 flushes including initial commit, full 256 KiB independent byte-array comparison after reopening; scatter/gather crossing a page boundary, write-input mutation isolation, invalid-range refusal, dirty abort and reopen, historical branch isolation, two workers racing on same revision with exactly one successful flush, flush waiter refusal on abort. Repeated after bounded queue and process-close changes. Earlier 3000-operation structural disk, durable Ground SIGKILL/recovery, 64-revision E-CPU-backed index and 1000 historical observations rerun successfully. Python and JS syntax checked. No benchmark or physical compression claim. Queue saturation, mid-flush failure and high-concurrency guest requests not yet qualified.

CI extends actual Linux acceptance with a disposable ext4 image on HistoryDevice: initialize disk, boot Alpine, mount/write/unmount/sync, fork clean branch, boot alternative and overwrite, then boot both separately and verify divergent bytes. Four boots are a test plan, not passed evidence. JSPI, acquired upstream runtime and ext4 tooling unavailable locally; preceding Linux CI queued at review. No original-kernel full regression.

Next: qualify the Linux tests; expose a conventional persistent session launcher with selected historical branch, qualify ordinary packages and E-CPU guest execution. Establish immutable store identity, disk-generation/snapshot sealing, portable coordinate witnesses, and native E-CPU pathway bindings. Measure end-to-end realization cost including SQLite and process IPC before changing default storage.

# C0.7 — Observation-realized storage

A conventional read is a projection of an admitted immutable Ground, not an instruction to use a particular backing device. ObservationDevice implements the read-only upstream BlockDevice shape. It accepts a caller-pinned coordinate receipt and ordered locally bound observation routes, verifies every new page witness independently, retains a bounded LRU of verified pages, and derives zero ranges from verified empty sibling subtrees. Root EMPTY commits an entirely zero disk. The selected realization does not change the requested logical bytes.

For a verified coordinate i, a zero sibling at depth k (root-down, zero-based) in a depth d tree certifies the range [floor(i/2^(d-1-k)) XOR 1 times 2^(d-1-k), plus 2^(d-1-k)). This is the existing Merkle zero-collapse convention, not a new general-purpose inference rule. The observer may derive those zero contents without contacting the interpreter. This relies on the admitted root and collision resistance; it does not imply privacy of other coordinates or confer remote write/observation authority. Caller admission covers the entire immutable root. The remote server still restricts requested witness coordinates.

Routes use the existing HistoryDevice.witness, remote_observer.py, and independent coordinate-witness.mjs; a new direct Node TLS client uses the existing VL-K length-prefixed protocol, certificate validation, request nonce and a 16 KiB response bound with five-second total deadline. It is not native E-CPU mailbox transport. Failed routes and corrupt witnesses are refused and the next route is tried, without publishing unverified output. Eight concurrent reads, eight routes, 1 MiB aligned scatter/gather requests and configurable 0..256 cached pages. Generic route callbacks are trusted local bindings and must enforce their own deadlines; no global per-read deadline or cancellation. Zero intervals may accumulate with observed geometry. Complete requested bytes are staged before scattering into caller views; failed later page leaves output unchanged. No writes, mutable overlays, snapshots, or distributed publication. No general privacy or malicious host DoS guarantee.

Evidence (Node 22, Python 3.13): one valid page witness following one rejected forged witness certified 8191 further zero pages of a sparse 64 MiB Ground; all subsequent page reads matched zeros with no additional route attempts. Cache hit, all-zero root without a route, invalid geometry refusal, read-only refusal, unavailable second page leaves entire output unchanged. Actual closed local worker falls back to direct Node-to-Python mutual TLS over loopback, two nonzero page witnesses verified; receiver terminated, certified zero still available and uncached nonzero refused. Independent 512 witness and 250 paired historical pathway regressions passed. No speedup or general compression claim: these are actual route-count reductions on deliberately sparse data, and each requested output byte is still materialized. Existing E-CPU leaf backing remains in use. No original kernel full regression, native E-CPU transport execution or actual Linux guest run in this pass. The new oracle is added to CI.

Next: qualify actual Linux raw read-only device, use real filesystem data to measure witness coverage, reduce repeated per-page authentication through bounded sessions and multiproofs, add structural procedural page laws with independent admission and explicitly costed selection. Preserve conventional realization as an admitted fallback, not as the definition of computation.
